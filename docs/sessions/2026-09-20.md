# Session: 2026-09-20

## Goal
Build a fast macOS app showing the current time in CEST, then iterate it into a proper resizable/closable window with a Preferences panel.

## Progress
- Scaffolded a Swift Package (no Xcode project) at `Package.swift` + `Sources/Clock/`, AppKit-based, `.executableTarget`.
- `main.swift`: `AppDelegate` builds the main menu (Preferences…/Cmd+, and Quit) and the main window.

- `Settings.swift`: `UserDefaults`-backed singleton (`Settings.shared`) with `use24Hour`, `showSeconds`, `showDate`, `fontSize`, `timeZoneIdentifier`, `backgroundColor`/`textColor` (hex-encoded `NSColor`), `alwaysOnTop`, `launchAtLogin`, `rememberWindowFrame`. - `PreferencesWindowController.swift`: `NSTabView` with Display / Time Zone / Appearance / Window tabs; time zone picker is a searchable `NSComboBox` over `TimeZone.knownTimeZoneIdentifiers`; launch-at-login uses `SMAppService.mainApp`.
- Window evolved from fullscreen borderless (`.borderless`, `.mainMenu + 1` level) to a normal titled/resizable/closable window (`[.titled, .closable, .miniaturizable, .resizable]`), centered, with optional frame autosave (`ClockMainWindow`).
- Verified: `swift build -c release` succeeds; launched via `.build/release/Clock` and confirmed visually each iteration.

## Decisions
- Kept everything in AppKit (no SwiftUI) for consistency across `main.swift` / `ClockView` / `PreferencesWindowController`, since the original window management (borderless fullscreen, custom levels) was already AppKit-native.
- Time zone is user-selectable but defaults to `Europe/Berlin` rather than a raw `CEST` offset, since `TimeZone` handles the CEST/CET DST transition automatically.
- `launchAtLogin` via `SMAppService.mainApp` is wired up but will silently fail to matter until the app is packaged as a real `.app` in `/Applications` — flagged in-UI with a hint label rather than blocked.
